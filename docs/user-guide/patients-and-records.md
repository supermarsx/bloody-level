# Patients and records

## Patients

Patients is the place to organize the people represented by imported reports. Search and filter the list, then open a patient to view their report history and analyte trends.

Patient fields include a display nickname, sex, date of birth, and notes. Keep notes factual and remember that they are stored in the encrypted local vault.

Use edit when a profile needs correction. Merge or delete only after checking the reports that will be affected; these actions change the way history is grouped.

## Records

Records provides the broader report and row view across the vault. Use it to find imported data that is not tied to the currently selected patient, inspect processing state, and review the available reparse or maintenance actions.

Reparse-all is useful after a deliberate Library or parser change. It can change mappings across many reports, so review the resulting audit entries and spot-check representative source PDFs afterward.

## Keep identity review explicit

Patient identification is part of the import review. A report with a missing or ambiguous patient should be corrected before it is used in a longitudinal comparison. Do not infer identity from filename alone.
